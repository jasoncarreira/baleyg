## PR #99 queue repair probes (new head verification pending)

Fail-before-fix probes reproduced all three Part A/T06 findings. After the scoped repair, a CLI-accepted durable row absent from daemon-local pending drives exceptional recovery to a new verified r1 pin. A CLI that accepted while an old owner still held the use lock waits until that owner releases it; it does not exit `recovery_required` with a silent queued ACK. A follower only marks a capture failure `index_failed` after it owns and verifies the leader fence, rechecks the current root and unchanged publication pin, and claims the FIFO head. A real unreadable source records that terminal state once rather than recapturing every 20 ms. A fresh Ready `requests.db` remains absent after current/by-ID reads and the queue directory is unchanged. `/api/jobs/current` excludes older rows from a replaced root.

Under an independent shared reader, a real browser POST Q1 and concurrently accepted CLI Q2 have durable seq1/seq2 while queued. After release, the daemon publishes new-generation r1/r2 in FIFO order; the CLI may have a stale pre-repair disposition, so it reopens **only the same verified root and already-existing index** before reporting completed Q2. A request admitted **after** a recovery capture cannot claim that earlier pin. Ctrl-C during a CLI request's own drain capture interrupts the work and leaves an honest durable `index_failed` row.

Owner-required post-ACK refresh hardening has a deterministic two-case race probe at the exact old existence-check/SQLite-open boundary. The old helper failed both: same-UID removal let `Store::open` bootstrap a new index; byte-identical 0600 inode replacement claimed stale success. The new helper uses only an existing SH use lock, same verified root identity, `O_NOFOLLOW` inode/path witness and an in-memory Store whose SQLite connection opens **read-only existing** bytes. It runs the normal recovery-baseline validation; pathname/inode and root fences are checked before and after. Removal leaves `index.db` absent and the accepted queue unchanged; restoring the saved old file yields the exact old generation/revision. Replacement is refused with unchanged pin/queue bytes. No `Store::open` initialization path is reachable. Corrupt, busy or missing publication fails closed without turning an accepted queue row into false `done`.

A separate test process committed a request pin while its durable row was `running`, recorded both facts, then exited with code 37 **before** the terminal queue write. The parent reopens the same storage and observes the published pin plus still-running row, then a new verified leader reconciles and reclaims that FIFO head to `done` at a later pin. In-process cached terminal-write retry avoids duplicate publication when that holder survives; **process death in this gap may cause another publication**. No across-process exactly-once guarantee is claimed. This is distinct from the older injected same-process completion-failure tests.

Unchanged Serve is the narrowly measured optimization here; an explicit no-change browser indexing command is still a durable request and takes its normal validated path. Any future no-change browser shortcut remains separate [#16](https://github.com/jasoncarreira/baleyg/issues/16) work with its own public contract. The prior draft-head mixed-large p95 was only 0.1525 s under its 5 s limit. Both unchanged cohorts were rerun on the final owner-hardened release SHA; mixed-large p95 **4.5031 s** now leaves **0.4969 s** margin. No runner or limit changed.
