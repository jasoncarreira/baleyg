# Local index and agent topology

**Status: normative for future Stages 2–4, not shipped behavior.** This is the #23 local topology and persistence contract for [#10](https://github.com/jasoncarreira/baleyg/issues/10), [#16](https://github.com/jasoncarreira/baleyg/issues/16), and [#17](https://github.com/jasoncarreira/baleyg/issues/17). It is not a claim about the current CLI, store, or tests. The owner accepted the direction on 2026-09-23; this ratification replaces the prior topology proposal. Semantic identity and evidence meaning belong to [#22](semantic-evidence/contract-v1.md); MCP wire form belongs to [#24](https://github.com/jasoncarreira/baleyg/issues/24).

Each checkout gets a path-keyed, disposable index outside the checkout. A Git-directory workspace UUID keys durable saved views and notes, including across a move; a non-Git checkout has path-keyed durable state. Local `baleyg mcp` is a future stdio entry point. Exactly one flock-elected leader for an opened root watches files and publishes native index rows. Other processes read verified snapshots and submit durable reconciliation requests. Except for the Git metadata UUID marker, Baleyg topology state stays outside the checkout.

| State | Location | Keyed by | Lifetime |
| --- | --- | --- | --- |
| Index (graph, cached source) | `<cache>/indexes/<root-key>/index.db` | Canonical root path | Cache; rebuilt freely |
| Leader lock | `<cache>/indexes/<root-key>/leader.lock` | Canonical root path | Removed with its index |
| Index use lock | `<cache>/indexes/<root-key>.lock`, beside the index directory | Canonical root path | Removed last, by the deleter holding it |
| Explicit index requests | `<cache>/indexes/<root-key>/requests.db` | Canonical root path | Survives index rebuilds |
| Fact cache | `<cache>/facts.db` | File content | Cache; size-bounded |
| Durable data (views, notes, future artifacts) | `<data>/workspaces/<record-id>/workspace.db` | Workspace UUID, or `path-<root-key>` outside Git | Durable; created on first write |
| Durable use lock | `<data>/workspaces/<record-id>.lock`, beside the record directory | Record id | Removed last, by `forget` holding it |
| Tokens and Jev/ACP ledgers | Explicitly configured paths | — | Durable; outside topology ownership |

The sections below define future observable behavior. An error name denotes refusal, not a shipped error API. The W checks are implementation/test fixtures for #10/#16/#17, not tests added by this document.

## T01 — Discovery and identity

- Resolve an explicit `--workspace` directory first; it is the root, never widened to an ancestor Git root. Without it, walk from cwd upward and select the nearest directory containing a `.git` entry; if none exists, use cwd. An encountered malformed/inaccessible marker is an error, never a reason to continue to another ancestor or silently use non-Git identity. For an explicit directory, use only its own `.git` marker; a subdirectory without one uses path identity.
- Require an existing, readable directory. Reject a final-component root symlink. Canonicalize ancestor components once, use the resulting absolute valid UTF-8 spelling without case folding or Unicode normalization, and capture `(device,inode)` from an opened root descriptor. Non-UTF-8 roots fail `invalid_root`. Reject implicit home/filesystem root after canonicalization. Explicit selection bypasses that selection guard, but not storage-overlap/security checks.
- `root-key = lowercase_hex(SHA-256(UTF8(canonical_absolute_root)))`, all 64 digits, no trailing separator except `/`, no domain prefix. This is a cache placement key, not a semantic ID. Persist the full root spelling and compare it on open; a hash-directory collision with a different spelling fails `root_key_collision` without overwrite.
- `.git` is either a current-user-owned, non-symlink directory, or a current-user-owned, regular, no-follow UTF-8 file of at most 4096 bytes containing exactly `gitdir: ` plus one nonempty path, optionally followed by one LF or CRLF. Reject NUL, embedded newlines, extra lines, trailing whitespace, and other prefixes. Relative targets resolve against the `.git` file's parent. Normalize `.`/`..` lexically, then traverse without symlinks; the target must exist, be a directory, and be owned by the current user. Reject missing targets, special files, symlink components, ownership mismatch, and unreadable components. Main checkout, worktree, submodule, and separate-git-dir use the selected Git directory, not `commondir`; each linked worktree therefore gets its own marker.
- Marker `<git-dir>/baleyg/workspace-id` has exactly 36 ASCII bytes in lowercase hyphenated UUID form, no newline; accept any non-nil canonical UUID, generate UUIDv4. Its `baleyg` parent is private; UUID is a private, regular, single-link file opened no-follow. Wrong permissions, owner, type, spelling, nil value, or extra bytes fail `invalid_workspace_id`; never regenerate an invalid existing value. A creator may make only the missing private `baleyg` child under the already-existing verified Git directory; it never creates Git-directory ancestors. After mkdir, fsync the new baleyg directory and its Git parent to persist that directory entry before publishing a UUID. A winner creates workspace-id with `O_CREAT|O_EXCL|O_NOFOLLOW`, writes fully, fsyncs the marker file, then fsyncs baleyg and the Git parent. Losers reread rather than choose another UUID. Every adopter, including a loser that sees 36 valid bytes before the winner has synced and an opener of a crash-left valid marker, must itself complete marker-file → baleyg-directory → Git-parent fsync on verified descriptors before treating the UUID as durably usable. A failed/unsupported fsync refuses with `workspace_id_not_durable`; no workspace.db initialization, save, or successful UUID-based record attachment may depend on it. The visible bytes alone are not a completed identity-creation acknowledgement. Only the transient empty/short file created by a concurrent writer may be retried, every 50 ms for at most 1 s; if still incomplete, refuse. Crash-left partial markers require owner intervention with Baleyg stopped, never automatic replacement.
- `record-id` is that UUID, or `path-<root-key>` when the selected root has no Git marker. A move changes index path/key but preserves Git durable identity. Copying the marker deliberately shares durable data. A non-Git move yields a new durable identity; the old record remains and is reported. Changing/replacing a marker during a process lifetime requires closing/reopening the workspace; never silently redirect an open durable connection.
- The marker is the sole permitted Baleyg write inside Git metadata (possibly inside the checkout); correct the existing absolute “nothing inside a checkout” wording. All DBs/locks remain external. On every root open, reject overlap with fixed cache/data locations or configured token/ledger paths, including canonical aliases and ancestors. Explicit home can therefore fail `storage_overlap`. This checks selected roots, not hypothetical unknown checkouts.

## T02 — Locations, file policy, and schema conventions

Retain every storage-table location from the proposal unchanged. `<cache>` and `<data>` are respectively `ProjectDirs::from("dev", "odin", "baleyg").cache_dir()` and `.data_local_dir()`. Failure to resolve them is fatal; no environment/CLI placement override. State roots must be distinct and outside selected workspaces. Token/Jev/ACP paths remain explicitly configured, external, durable, and outside topology ownership.

Private application directories are 0700; DBs, UUIDs, locks, sidecars, and staging files are 0600, current-user-owned, regular/single-link where files, with no-follow opens and post-open owner/type/device/inode checks. Do not chmod, follow, or delete unexpected objects; fail `unsafe_state`. Use descriptor-relative operations for managed descendants. Do not claim a sandbox against hostile concurrent ancestor replacement.

All new topology databases use schema version **1**, recorded by `PRAGMA user_version=1`, with singleton identity metadata; do not reuse current Store version 3. SQLite integers below are nonnegative signed-64-bit values unless stated; times are UTC epoch milliseconds for retention/reporting, never leader leases. IDs denoted `U` are generated UUIDv4 storage handles; hashes `H` are 64 lowercase hex characters. Text is valid UTF-8. SQL columns are NOT NULL unless `?`; singleton PK is integer 1. Unknown/missing columns, wrong metadata, or invalid rows fail validation, with the per-database disposition below. All JSON uses #22 canonical JSON encoding; topology envelopes have exactly the named fields. Busy timeout is 5 s for index/request/durable DBs and 100 ms for facts. Busy timeout returns a retryable local failure, not success.

**`index.db` (WAL, synchronous=FULL; disposable):**
- `index_meta(id PK, root_key H, root_path TEXT, root_dev INTEGER, root_ino INTEGER, schema_version=1, extractor_version TEXT, index_generation U, index_revision INTEGER, reconciled_incarnation U?, scan_started_ms INTEGER?)`; generation is fresh on creation/rebuild; revision begins at 0 with no evidence and increments once per successful publish, including a successful no-change full reconciliation. `reconciled_incarnation=null` means unavailable. Extractor version is a build-supplied exact compatibility string covering native extraction/context serialization. Revision exhaustion requires rebuild with a new generation before another publish. These are internal storage counters, not a definition of #22 revision IDs or client basis.
- `files(source_set TEXT, language TEXT, path TEXT, device INTEGER, inode INTEGER, size INTEGER, mtime_ns INTEGER, ctime_ns INTEGER, content_hash H, extraction_context_digest H, source BLOB, PRIMARY KEY(source_set,language,path))`; `path`/language/source-set refer to #22 DocumentKey. Timestamp ns columns are signed-64-bit (pre-epoch values are allowed). Source bytes/hash/length must agree with the referenced Document. Stat metadata alone cannot create semantic evidence.
- `tracked_inputs(input_class TEXT, input_key TEXT, present INTEGER, device INTEGER?, inode INTEGER?, size INTEGER?, mtime_ns INTEGER?, ctime_ns INTEGER?, content_hash H?, captured_bytes BLOB?, PRIMARY KEY(input_class,input_key))`; the closed classes, keys and limits are T08. Present is 0/1; absent rows have all stat/hash/bytes fields null, present rows have all non-null. Descriptor inputs use zero stat fields and exact captured descriptor bytes. This is a disposable topology capture inventory, not a competing #22 identity or revision schema. Replace it atomically with the source snapshot; never infer a #22 basis digest from stat values.
- `records(kind TEXT, ordinal INTEGER, payload_json TEXT, PRIMARY KEY(kind,ordinal))`. Closed kinds: `Producer`, `SourceSet`, `Revision`, `Document`, `Coverage`, `Provenance`, `Declaration`, `Symbol`, `DeclarationBinding`, `TypeRelationship`, `Call`, `ControlRegion`, `Reference`, `CallBinding`. Each payload is exactly that #22 record, not a new competing schema. Nested types remain nested. Within each kind, sort canonical payload bytes, remove byte-identical duplicates, and assign contiguous zero-based ordinals at publication; conflicting identities still fail #22 validation, never first-win. References are validated against the whole snapshot before commit; ordinals are private storage positions, never stable IDs. This generic envelope avoids prescribing new production semantic tables.
- `lookup_dependencies(owner_kind TEXT, owner_ordinal INTEGER, source_set TEXT, language TEXT, dependency_kind TEXT, lookup_key TEXT, PRIMARY KEY(all columns))`; owner_kind is `Call` or `Declaration`, referring to its current native measured-syntax records row, never to a semantic Reference/CallBinding row. Dependency kinds and matching policy are T09. These are native reassembly scheduling hints, not bindings or semantic resolution results. Regenerate them atomically with native records and remap ordinals after canonical sorting.
- `declaration_surfaces(source_set TEXT, language TEXT, path TEXT, syntax_id TEXT, surface_json TEXT, PRIMARY KEY(source_set,language,path,syntax_id))`; surface shape is T09, identity meaning remains #22. No saved views/notes, request states, or user-owned artifacts in this DB.

**`facts.db` (rollback journal DELETE, synchronous=NORMAL; optional shared cache):**
- `fact_meta(id PK, schema_version=1)`.
- `facts(language TEXT, extractor_version TEXT, extraction_context_digest H, content_hash H, payload BLOB, payload_hash H, payload_bytes INTEGER, last_used_ms INTEGER, PRIMARY KEY(language,extractor_version,extraction_context_digest,content_hash))`.
- Payload is the extractor-version-owned path-neutral byte record, not #22 assembled IDs; context digest is SHA-256 of exact canonical `{language,options,toolchainHash}` where v1 `options` is exactly `{}` (no configurable native extraction options) and `toolchainHash` is the captured extractor executable hash. Config-dependent/future extractors cannot use this v1 cache unless their extractor version declares a new closed context encoding containing every extraction-affecting input; otherwise bypass cache. Root/path/mtime and workspace ID are forbidden in path-neutral contexts. This envelope does not define a new extractor AST. Verify payload hash and length; invalid entries are misses and may be deleted. INSERT OR IGNORE is idempotent; a conflicting payload for the same key disables use of that key for the operation and emits `fact_conflict`, never changes extracted evidence to match the cache.
- Cap payload at 8 MiB/entry, total payload at 256 MiB, and 100,000 entries. Evict within the insertion transaction until both totals fit, oldest `last_used_ms` first, then full PK byte order. Oversized entries are not cached, but extraction can continue. Successful reads update LRU best-effort; clock rollback uses `max(old,now)`. Page size 4096, max_page_count 131072 (512 MiB DB bound); allocation/lock failure bypasses cache. Short transactions only; no held fact snapshot during extraction. SQLite journal overhead is separate temporary overhead, not an alleged aggregate disk cap.
- Version mismatch rebuilds fact tables transactionally in place; never unlink an open shared DB. Corruption that prevents this disables the optional cache and reports it; manual removal requires all Baleyg processes stopped. No new fact-file deletion lock or automatic file recreation is introduced.

**`workspace.db` (WAL, synchronous=FULL; durable):**
- `workspace_meta(id PK, schema_version=1, record_id TEXT, created_ms INTEGER)`.
- `items(item_id U PK, kind TEXT, title TEXT, body TEXT, created_ms INTEGER, updated_ms INTEGER)`; kind is `view|note`, title 0–256 UTF-8 bytes; view body is a canonical JSON object (opaque presentation preferences only, no authoritative identity/pin fields), note body is plain UTF-8 text. Body ≤1 MiB, JSON nesting ≤32, update time ≥creation time.
- `anchors(item_id U, ordinal INTEGER, anchor_json TEXT, PRIMARY KEY(item_id,ordinal), FOREIGN KEY item_id REFERENCES items ON DELETE CASCADE)`; canonical payload is exactly #22 DurableAnchor. 0–1024 contiguous anchors/item; do not alter anchors during reattachment/read or persist a guessed replacement. #22 validates capture and computes attachment against an available snapshot. Missing historical source is not permission to erase the captured anchor.
- `known_roots(root_key H PK, root_path TEXT, last_saved_ms INTEGER)`; update only on successful user saves. It supports “last known location missing” reports, not a global checkout registry or UUID ownership claim.
- `artifacts(artifact_id U PK, media_type TEXT, content_hash H, payload BLOB, created_ms INTEGER)` is **reserved and must remain empty in v1**. No insert operation is admitted by #23. A future artifact feature must specify its format/admission; topology already assigns its durable retention/deletion boundary. There are no implicit future fields accepted today.
- Enforce ≤10,000 items and ≤64 MiB combined UTF-8 item/anchor payload per record transaction. Reject an over-limit save atomically as `durable_limit`; retain the old record. Schema mismatch/corruption is `durable_unavailable`, never rebuild/migrate/delete. Backups/manual export are owner concerns outside this issue.

**`requests.db` (WAL, synchronous=FULL; persistent scheduling state, not user durable data):**
- `request_meta(id PK, schema_version=1, root_key H, root_path TEXT, root_dev INTEGER, root_ino INTEGER, last_opened_ms INTEGER, retired_ms INTEGER?, retirement_reason TEXT?)`; last_opened_ms is the authoritative open-age metadata under T10, not a native index row. New metadata uses current time and null retirement fields. Retirement fields are both null while active, or a time and literal `root_changed`; retirement fences further admissions under T04/T05.
- `requests(seq INTEGER PRIMARY KEY AUTOINCREMENT, request_id U UNIQUE, operation TEXT, root_dev INTEGER, root_ino INTEGER, submitted_ms INTEGER, state TEXT, claimant U?, attempts INTEGER, cancel_requested INTEGER, started_ms INTEGER?, finished_ms INTEGER?, error_code TEXT?)`.
- Only `operation=reconcile` is admitted. It requests a full stat reconciliation of the captured root; it does not carry paths, arbitrary SQL, overlays, or command text. State is `queued|running|done|failed|cancelled`; booleans are 0/1; attempts is 0–3. Queued rows have null claimant/start/finish/error and attempts 0 initially; running rows have claimant/start and no finish/error; terminal rows have finish, retained claimant/start if ever claimed, and error only for failed. Reclaimed work transitions directly to running with the new claimant, increments attempts and replaces start. Successful commit/done is not a client wire result-basis definition.
- Request ID is the idempotency key for the retention lifetime. An identical resubmission returns the existing row without another execution; differing operation/root identity is `request_conflict`. After eviction, reusing a key is a new submission; callers must not treat this as permanent deduplication.
- Version mismatch or integrity failure refuses new/claimed work as `requests_unavailable`, without migration or automatic deletion. Never silently lose accepted rows. Rebuild/recreation of index.db leaves this DB and its sidecars untouched.

<a id="T03"></a>
## T03 — Lock lifecycle and durable creation

- Both use locks live beside their directory exactly as in the storage table. Open/create, acquire flock, then compare fstat(fd) with no-follow stat(path), including device/inode/owner/type. If missing/different, release/close and retry from open. At most three identity-race retries per operation; then `state_busy`. Lock contents are empty. Close all protected DB connections and SQLite statements before releasing the use lock.
- Index use **shared** is required while index.db, requests.db, or leader.lock is open; request appenders and waiting clients count as users. Durable use shared is required while workspace.db is open. Use exclusive, nonblocking for index directory deletion, exceptional index-file recreation, durable first creation, and forget. Never upgrade while keeping an open protected DB; no blocking shared→exclusive upgrade. Failure to get exclusive means `busy`/skip, not forced deletion or PID killing.
- For ordinary opening, missing directories may be created under a verified shared lock; leader.lock and schema initialization still serialize via their own mechanisms. For first durable write, require T01 successful UUID durability acknowledgement when using a Git record ID, acquire exclusive use, recheck absence, and create directory/DB. For each newly created application/state-directory ancestor, fsync the child and its containing parent after mkdir, walking from the highest newly created entry down; no saved record may depend on an unpersisted parent entry. Commit identity plus first item/anchors/known root in one transaction and fsync the record directory before reporting first-save success. Publish the record only after that commit. Release, reacquire/verify shared, and reopen if needed. Another first writer retries/reopens the committed record rather than overwriting it. Reads of absent records return empty without creating record directory/DB (an incidental empty use-lock file is allowed).
- A first-write failure removes only its uncommitted newly created DB/directory while still exclusive. Crash-left empty/uninitialized first-create residue is not a valid record: report it, do not auto-initialize over it or call it saved data. `forget` can remove it after confirmation. A valid record may become empty after explicit item deletion and remains durable until forget; “empty records never exist” becomes “read-only use never creates a durable record.”
- Whole-directory deleter holds verified exclusive use for the operation, deletes only recognized owned members, fsyncs parent, unlinks use lock **last**, then unlocks/closes. A retry racing the unlinked inode must reopen and verify the new pathname. Unexpected files/symlinks stop deletion, not recursive traversal through them. Record/index locks may be left behind after failure; they are not liveness evidence. Index files include DB/WAL/SHM and leader/request files; durable files include DB/WAL/SHM only. Never remove token/ledger trees.

<a id="T04"></a>
## T04 — Leader, incarnation, readers, and takeover

- Acquisition order is index-use shared → leader.lock exclusive nonblocking; immediately verify leader lock path identity. Each process (stdio MCP, browser daemon, CLI) may contend. Pre-generate a fresh incarnation; after verification the successor's first mutation writes it to leader.lock, truncates to exact length, fsyncs, then begins any DB work. Contents are canonical `{version:1,incarnation:U,rootKey:H,rootDev:integer,rootIno:integer}`; no PID/time is authority. Invalid/partial contents mean not ready, never reuse old contents.
- Lock winner is leader until graceful release/crash. Only it watches and mutates native index rows. It first clears/invalidates the reconciliation marker and performs a full root-checked reconcile, then commits marker=current incarnation with publication. Startup failure leaves evidence unavailable; it may retry at the 30 s failed-reconcile backoff. Persistent root/security/schema failures release leadership and require operator/reopen action.
- Nonleaders retry nonblocking acquisition at next request and every 1 s while active. A no-leader explicit requester joins the same election and drains accepted work; inability to win is not a rejection. CLI waiting may end after 30 s with queued/running status; the accepted row survives. A CLI leader with no other clients exits after draining accepted jobs and closing DBs; daemons/MCP remain until their process shutdown. Graceful shutdown stops admissions locally, cancels uncommitted native work, closes DBs/watcher, releases leader then use lock; requests stay available for takeover.
- A follower serves only after (a) root identity matches, (b) nonblocking exclusive leader probe is contended (if it wins, it must become leader/reconcile, not serve as a follower), (c) marker contents are valid, (d) its WAL snapshot has matching reconciled incarnation, and (e) after materializing bounded output, root, marker contents, and contended leader probe still agree. The leader uses its actually held lock in place of probing its own lock. If any check fails, discard output, retry once against a fresh snapshot; otherwise `index_not_ready`. No cached evidence is served when no leader holds the lock. Read transactions have a 5 s deadline; exceed it, close and return `read_timeout`, allowing WAL checkpoint progress. Index read transactions do not take SQLite write locks; T10 ordinary-open registration separately writes request metadata before opening a read snapshot. “Never block” does not promise no resource/I/O contention or zero-cost opening.
- Explicitly ratify the narrow lock→incarnation-write race: a follower can serve the predecessor's last reconciled snapshot if both checks occur after successor flock and before the new marker is visible. **There is no finite wall-clock bound under process suspension.** Do not retain the false claim that this cannot exceed watcher latency. No scans/jobs/intentional waits may occur between verification and writing the new marker; tests pause at these exact barriers. Once the new marker is visible, predecessor marker mismatch must refuse until successor reconciliation commits. Lock loss after the final check is an ordinary response race, not a linearizable filesystem freshness promise.
- Root descriptor `(dev,ino)` is checked before each scan, before publication, and before/after serving. Missing/moved/replaced root yields `root_changed`: stop admissions/native publication, cancel uncommitted native work and refuse reads. A detecting leader must first attempt the bounded request-retirement transaction below while still holding verified leadership, then close DBs/watcher and release locks. A detecting follower never completes requests: close/release and report root_changed. No process scans the replacement at the old pathname or follows the moved root to an unadmitted location.
- Retirement is an idempotent BEGIN IMMEDIATE transaction on a valid requests.db for its captured old root identity: set `retired_ms=now` and `retirement_reason=root_changed`, and change all its queued/running rows (at most 4096) to terminal failed with `error_code=root_changed` and `finished_ms=retired_ms`, preserving request IDs, attempts and any claimant/start. Already terminal rows remain terminal. Before adding these terminal rows, prune the oldest ordinary terminal history as needed to keep the 4096-terminal cap; a retired DB has no further admissions or execution. Preserve the newly failed rows for at least 24 h after retirement, overriding ordinary terminal eviction during that quarantine. No root pathname access is needed to commit the recorded failure. On SQLite/validation/security failure, report `request_retirement_pending`, leave accepted rows/DB untouched, close and release; never fake completion. A crash before commit leaves nonterminals for recovery, a crash after commit leaves the same observable terminal failures.
- Recovery requires no replacement at the old pathname. A later non-report GC pass can validate a missing or device/inode-mismatched recorded root, acquire verified exclusive index use, then acquire/verify leader.lock and write a fresh incarnation bearing the recorded old identity solely for administrative retirement. It may run the same request-retirement transaction, never native extraction/publication; T04's startup-reconcile requirement has this explicit maintenance-only exception. It closes all protected DBs before releasing either lock. Permission-denied/unreadable root, unknown metadata, incompatible/corrupt request DB, or any contention is report-only/skip; no timeout can override a lock. If a retired root later reappears, retirement is not undone and its accepted requests are not replayed.
- A replacement or returning root may reuse the path-keyed directory only under verified exclusive index use, after validating/completing retirement and allowing its 24 h request-failure quarantine to expire. Until then open returns `root_retired` without rebinding. After the quarantine, terminal history may be pruned under T05, request metadata may be rebound with null retirement fields, and the derived index is rebuilt; old-root requests never execute on the replacement. User durable identity is independently rediscovered. Clock rollback postpones quarantine expiry. Eventual cleanup requires a later successful GC/open pass; no cleanup while processes are stopped is promised.

<a id="T05"></a>
## T05 — Ordered work and durable requests

- One active native job. Native pending memory contains at most one coalesced event batch and one full-reconcile flag; durable requests remain on disk, not a second unbounded memory queue. At each scheduling boundary, alternate ready maintenance work and the lowest-seq queued/reclaimable explicit request when both exist. Startup/takeover full reconcile is the one priority exception. Once the active job terminates, each ready class therefore waits for at most one other-class job; no wall-time fairness claim beyond job deadlines.
- Claim the lowest eligible seq in BEGIN IMMEDIATE, set running/current incarnation/start, increment attempts, commit before execution. Only the currently locked leader can claim/run/complete; request writers can insert and request cancellation, plus the metadata-only ordinary-open registration in T10; they cannot claim, execute or complete work. Incarnation is a fencing/claim identity, **not a timed lease**. A successor may reclaim old-incarnation running rows only after holding verified leader lock; timeout/PID checks never steal a live leader. Reclaim on attempts=3 marks failed `attempt_limit`; otherwise execute again. All ordinary terminal execution failures are failed, not endless automatic retries. The internal stat-race retry in T08 is within one attempt.
- At-least-once execution is intentional: index publication and request completion use separate DB transactions. Crash after publish/before done may repeat a reconciliation and advance an internal revision again, never regress source state. Accepted queued rows survive process death and index rebuild. Crash before request insert commit means not accepted; crash after it means durable acceptance even if caller missed the reply.
- Cancellation is a conditional update `cancel_requested=1` for nonterminal rows. Queued cancellation becomes terminal cancelled without execution; running work checks before expensive phases and immediately before publication. After index commit cancellation is too late and request may finish done. Disconnect/timeouts do not cancel accepted work. No rollback of committed index state to honor late cancellation.
- Maximum 4096 nonterminal rows and 4096 terminal rows. Delete terminals older than 24 h; if terminal cap would be exceeded, evict oldest `(finished_ms,seq)` first even inside 24 h. Admission/count/pruning is transactional. When nonterminal cap is full, wait/retry at 100 ms intervals for at most 5 s, then `queue_full` **not accepted**. Same for storage/SQLite failure: explicit failure, never pretend queued. Replace “requests are never rejected” with “leadership contention does not reject requests; invalid inputs/resource failures have explicit bounded outcomes.” No-leader is not queue_full.
- Root mismatch rows fail and fence admissions through T04 retirement. Admission checks root identity and null retirement fields inside the insert transaction; if retirement commits first, no later insert can be accepted, and if insert commits first, retirement includes that row. Root disappearance after the final admission check is handled by retirement, not execution on another root. Request metadata is rebound only under exclusive index use after T04 quarantine expires; root-path/key stay fixed. Incompatibility/corruption blocks reset without discarding rows. Ordinary T05 pruning never removes quarantined root_changed failures.

<a id="T06"></a>
## T06 — Watcher and triggers

- Future notify watcher handles create, modify/content/metadata, remove, and rename (old path deletion + new path addition). Unclassifiable events, ignore/config changes, overflow, lost-event notification, watch-limit exhaustion, wake, and bulk changes set the full-reconcile flag. Symlink events never authorize traversal.
- Debounce 200 ms after most recent event, with a 2 s maximum from the first event. Coalesce normalized relative paths into a set; at **more than 4096 distinct paths**, clear it and promote to full reconcile. No event list grows beyond that cap. Rename counts both paths. Relevant config changes always force full reconcile and context recomputation.
- Full stat reconcile on leadership, every 60 s while leader (missed timers coalesce), and each explicit request. Poll-only fallback if watcher cannot start/continue; expose degraded watching status, but reconcile remains required. Failed background reconcile retries no sooner than 30 s; no busy loop. Local deadlines use monotonic time; wake forces full reconcile rather than trusting paused timers.
- Explicit browser indexing always appends a request, including in the same process as the leader; never calls a second direct writer. CLI explicit indexing follows the same rule. MCP read tools are read-only; startup/takeover/periodic maintenance may index. Dependency overlays and future semantic owner imports cannot mutate native rows or bypass the index writer fence; semantic-import payload/command implementation is deferred. Any future admitted overlay mutation must use the leader's same serialization/publication boundary. Request v1 rejects unsupported operations; it does not silently admit an undefined import payload.

<a id="T07"></a>
## T07 — Rebuild and exceptional recreation

- On first open, check identity/version and SQLite quick_check; validate record invariants before use. Schema/extractor mismatch or detected logical integrity failure blocks new serving and requires a leader rebuild, not a migration. Within the existing index file, atomically replace index-owned tables, validate a full snapshot, set fresh generation/revision=1 and current reconciled incarnation. Prior WAL readers may complete their already-open coherent snapshots if their T04 checks pass; new reads cannot use incompatible schemas. Failed/cancelled rebuild rolls back entirely; an incompatible/invalid old index remains unavailable, not served as fallback. Requests, facts, workspace data, and UUID do not rotate.
- Only `SQLITE_CORRUPT`, `SQLITE_NOTADB`, or an index format failure that prevents transactional table replacement authorizes **exceptional index-file recreation**. Busy, full disk, permissions, I/O errors, and transient open failures do not authorize deletion. Readers encountering corruption close all index/request connections and release shared use, return `index_recovering`, and may retry open once after 100 ms; if still unavailable return, not spin.
- Recovery requester closes connections, releases leader and shared use, then tries verified exclusive use nonblocking. If busy, leave files untouched and retry recovery on the 1 s election tick; no live-reader killing. Under exclusive use reacquire/verify leader.lock, write fresh incarnation, recheck root/need, remove **only index.db and its WAL/SHM**, fsync directory, create fresh index DB, and complete a full rebuild. Keep requests.db and leader.lock intact. Close/release and re-enter ordinary open/election protocol before serving; if another leader wins, follow it. Do not rely on an atomic flock downgrade.
- Crash after unlink/before creation leaves absence, not a half-valid served index; next exclusive recovery finishes. Partial recreation/schema-init is unavailable until fully validated. Deletion/create/fsync failure reports `index_recovery_failed` and leaves no success marker. Exclusive use ensures no old DB incarnation is open at the same pathname when a new one appears.

- Pin source walker behavior to `src/indexer.rs:127-179`: ignore crate with `require_git(false)`, no symlink following, hidden exclusion; exclude `.git`, `node_modules`, `.venv`, `.baleyg`; exclude `target|dist|build` except their legal locations below `src/(main|test|testFixtures)/java`. Classes (2)-(6) use `tracked_inputs`; enumerate every listed root config/manifest even when absent or ignored. The root config/manifest inventory is evidenced by the targeted lookup `src/indexer.rs:223-246`. No nested manifests/config extensions, downloaded dependencies, environment variables, external compiler installations, Git config, or semantic-producer artifacts are implicitly admitted or read. An extractor requiring any such input must refuse this v1 capture profile; future semantic admission is deferred, not licensed to claim those bytes were captured.
- Bound the admission set to 1024 SourceSet descriptors/1 MiB combined descriptor bytes. Bound the visited-directory set to 100,000 directories (including root); an ignored/excluded subtree is not visited. Probe its two ignore filenames before enumerating a visited directory, without applying hidden-file filtering to those probes. Bound each ignore/config/manifest file to 2 MiB, their combined captured bytes to 64 MiB, and the executable to 256 MiB. All tracked rows count toward the 1,000,000-row cap; their stored byte payload also counts toward the 512 MiB non-source payload cap. Config/manifest/toolchain bytes may be binary; UTF-8 source-text validation applies only to sources. Unreadable or unsafe present inputs, limits, or unstable reads abort publication with T08's existing failure outcomes; no silent omission.
- Every full reconcile re-enumerates admitted sources and visited directories, probes all root config/manifest names including prior absences, and captures/hashes every present ignore/config/manifest/toolchain input even if its stat tuple is unchanged. Stable descriptor bytes are recaptured from the open admission snapshot. Read ignore rules from those captured bytes, not a second uncontrolled filesystem read. Additions/removals and hash changes invalidate the old capture and force full native reassembly of the admitted workspace; a changed ignore file can admit/exclude source paths in the same job. A changed executable returns `toolchain_changed` and requires process restart and recapture, not merely workspace reopen in the same process, rather than running old code under a new executable hash. Before publication re-probe presence and rehash these non-source file inputs; a difference repeats the full walk within the existing three stabilization rounds, then `unstable_input`. The 60 s full reconciliation therefore detects a persistent config/manifest/ignore change even if every watcher event is lost. This is eventual reconciliation after a successful bounded scan, not a 60 s completion/freshness guarantee.
- Exact captured bytes feed the native producer's #22 Revision toolchain/config/dependency components; the component encoding/identity and freshness meanings remain #22-owned. The inventory is capture evidence, not a substitute hash algorithm or a semantic completeness attestation. Native path-neutral facts still use T02's executable/options-only context because this v1 extractor does not consume project configs; project config/manifest/admission changes invalidate assembly and revision capture, not those path-neutral payload bytes. An extractor that consumes more inputs must bypass that fact profile as T02 requires.
- Hard caps: 100,000 discovered admitted source files, 2 MiB/source file, 1 GiB total captured source bytes, 1,000,000 index records/dependency/surface rows combined, 512 MiB combined canonical record/dependency/surface payload, 10 min/job, three read/stabilization attempts/path per job. Exceeding a cap, unreadable admitted file, walker error, invalid source-relative path/UTF-8 text, or unrecoverable extractor error aborts the job with `scan_limit|scan_failed|extraction_failed|job_timeout`; keep the previous valid publication. Never silently truncate and call a full reconcile complete. Fact-cache oversize is only a cache miss; durable/request limits have their own outcomes.
- For source files only, compare `(device,inode,size,mtime_ns,ctime_ns)` to previous committed file rows. Hash new/stat-changed/context-changed files and files with mtime or ctime **at or after previous scan start**, using timestamp precision reported by the filesystem (round previous scan start down to that precision). Wall-clock rollback or unknown timestamp precision forces all-file hashing. Record scan start only on successful publication. Same-size preserved-mtime writes are caught by ctime where the platform provides it; do not promise defense against hostile filesystem metadata manipulation.
- For each read, open no-follow nonblocking regular file, validate identity, stat before/after reading, enforce byte limit while reading, and verify byte count and stat stability. Retry unstable files up to three attempts, then `unstable_input` and abort. Missing previously indexed files become deletions; newly discovered files become additions. Unsupported/ignored files are excluded by the stated discovery policy, not silently dropped from an already-admitted snapshot.
- Build from immutable captured bytes off-transaction; lookup facts by exact tuple and assemble path/source-set/revision identity using #22 only. Before commit drain pending watcher paths, reread changed ones, and repeat bounded stabilization; a full-reconcile flag invalidates a partial batch and promotes the same job to full scan. Three stabilization rounds/job maximum, then unstable_input and leave a reconcile pending. Check cancellation, limits, root identity and held leadership immediately before commit. Events after the final cutoff remain pending for the next job; no instantaneous filesystem snapshot or zero watcher latency is promised.
- One BEGIN IMMEDIATE publication replaces the tracked-input inventory and affected file/record/dependency/surface rows, applies T09 native reassembly, advances internal revision, and commits reconciled marker with graph/source bytes. A failed/cancelled transaction preserves the preceding snapshot. No cross-file transaction with requests/facts/durable records is claimed. Background failure retains old evidence only when its schema/integrity and current-incarnation reconciliation remain valid; initial takeover/rebuild failure has no valid marker.

Retained captured semantic artifacts and their captured revision/supporting records remain historical and unmodified; #22 alone evaluates their requested-snapshot freshness and target-byte checks when selecting/using evidence. ## T10 — Cleanup, reporting, and forget

- Open age is stored only in `requests.db.request_meta.last_opened_ms`; remove `last_opened_ms` from index_meta. After taking verified index-use shared and validating active root/request metadata, every successful ordinary opener (leader, follower, CLI requester or request-waiting client) commits `last_opened_ms=max(old,now)` in a short request-DB transaction before reporting open success or beginning its index read snapshot. This metadata-only registration is the explicit exception to the request-writer insert/cancel-only rule, not a write to native index rows. Failure to register returns an open failure within the 5 s busy timeout; do not silently serve an unregistered open. Existing open users remain protected by shared use even without more age writes. First initialization is serialized before follower registration; no follower creates or mutates index tables. Administrative GC/report/retirement inspection never registers ordinary use. Leaders may attempt GC at most once per 24 h per process; it is safe if multiple leaders attempt because deletion is exclusive. Restart may schedule another attempt; do not imply a global once-daily coordinator. Clock rollback postpones age-based deletion rather than making state old.
- Enumerate only direct correctly named owned index directories and their validated root metadata. Delete a cache whose root is missing or has a different device/inode, or one unopened for **at least 30×24 h**, only with verified exclusive use nonblocking. Recheck root identity and request_meta.last_opened_ms after locking; age-based deletion requires valid request metadata and uses this authoritative value, never index creation/publication time. Permission-denied/root-unreadable is not “missing.” Unknown/corrupt metadata is report-only. Nonterminal requests prevent deletion even for missing/old roots. For a proved missing/replaced root, non-report GC first performs T04 locked administrative retirement and keeps the directory for its 24 h failure quarantine. After quarantine, a later pass may delete the now-terminal cache if still missing/replaced or age-eligible; never silently discard nonterminals. Ordinary terminal request history is disposable; quarantined root_changed failures are not disposable until quarantine expires. No retirement is attempted for an existing matching root merely because its index is old. Any live reader/leader/request DB user causes skip-busy.
- Facts evict via T02, never delete the shared file automatically. Durable records are never automatic-GC. `baleyg gc --report` is read-only: report eligible/skipped-busy/unknown index entries and durable IDs, item counts/bytes and last-saved known paths that are missing; do not claim a UUID has no copies elsewhere. Include retirement/pending-retirement status and retained request_id/state/error_code rows for missing/retired caches so failures remain inspectable without reopening that workspace; reporting performs no retirement, age registration, pruning, or schema initialization. Do not create missing durable DBs while reporting. Tokens/Jev/ACP ledgers and legacy state directories are neither scanned for deletion nor migrated.
- `baleyg forget <record-id>` accepts only canonical UUID or `path-` plus 64 lowercase hex digits, never a supplied path. Acquire verified durable-use exclusive nonblocking **before** inventory/confirmation; on contention return busy without deletion. Display record-id, counts, total payload bytes and known roots, and explicit warning that every checkout sharing the UUID loses these saved records. Interactive confirmation requires typing the exact record-id. Noninteractive use without `--yes` refuses; `--yes` bypasses prompt but still reports inventory/warning. Invalid/corrupt records report unknown contents and require the same explicit confirmation.
- After confirmation remove the record directory and recognized sidecars, fsync parent, unlink use lock last. Output `forgot <record-id>` only on complete success; absent record is idempotent `not found`. Failure reports incomplete deletion, never success. Do not remove workspace UUID, indexes, facts, requests, token, or ledgers. A later explicit save can create a new empty-then-committed record under the same UUID. No reset of shared identity and no undo promise.

## T12 — Worked checks

All `U_*` UUIDs and `H_*` hashes below are **fixture placeholders, not identity vectors**. `R` is the captured root `(path,dev,ino)`; `I` its index directory; `Q` its requests.db; `D` its durable record; `G1/G2` are distinct index generations. Unless specified, files/metadata are valid, locks are free, and a successfully reconciled leader holds shared index use plus exclusive leader lock. A failed publish retains the preceding committed rows and generation. These are future Stage 2–4 scenarios, not executable tests shipped here.

<a id="W01"></a>
### W01 — Selection and Git pointers

Initially `/repo/.git` is a private directory, `/repo/sub` has no marker, and `/plain` is non-Git; no index or durable rows exist and no locks are held. In order, an explicit `/repo/sub` selects only that directory with `path-H_sub`; implicit cwd `/repo/sub` selects `/repo` with Git `U_repo`; implicit cwd `/plain` selects `/plain` with `path-H_plain`. Each accepted open creates/uses its own `I`/`Q` identity, with generation only after leader reconciliation; no `D` exists before a save. Implicit home and `/` refuse `invalid_root`; explicit home is allowed only if it does not overlap fixed state or token/ledger paths, otherwise `storage_overlap`. A final root symlink and invalid UTF-8 root refuse `invalid_root`. Replace `/repo/.git` successively with a valid `gitdir: ../gitdirs/w1` file and private target (accepted for a linked worktree), then use separate valid main, submodule and `--separate-git-dir` targets: each selected Git directory has its own marker, not `commondir`. Malformed prefix, extra newline/whitespace, >4096 bytes, missing/foreign-owned/symlink target or inaccessible marker refuses without searching higher ancestors or creating rows. A subdirectory explicitly selected without its own marker stays path-identified.

<a id="W02"></a>
### W02 — Exclusive UUID creation and crash barriers

Start with private Git directory, absent `baleyg`/`workspace-id`, no `D`, two openers and no durable lock. A creates the directory and exclusive marker `U_a`; B loses `O_EXCL`, observes A's short marker, retries 50 ms apart for at most 1 s, reads exactly 36 valid lowercase non-nil ASCII bytes, then independently fsyncs marker → baleyg → Git parent before attaching. Both use `U_a`; only a first successful save creates `D/U_a`. At crash barriers (i) after baleyg mkdir before Git-parent fsync, (ii) after 36 bytes before marker fsync, (iii) after marker fsync before baleyg fsync, and (iv) after baleyg fsync before Git-parent fsync, neither the creator nor a racing adopter may acknowledge a durable ID or save; reopening a valid marker completes **all** fsyncs first, while fsync failure yields `workspace_id_not_durable`. A crash-left partial marker, invalid full marker, nil or uppercase UUID refuses `invalid_workspace_id` (concurrent transient short writes alone may retry); never replace it automatically. After acknowledged first save then crash/reopen, `U_a` and committed `D/U_a` remain reachable. A copy of Git marker to another checkout shares `D/U_a`; its path-keyed index has another `I`/generation.

<a id="W03"></a>
### W03 — Move, retirement, and replacement

Initially Git `/old` has `U_a`, `I/H_old` at `G1`, Q rows seq 1 queued and seq 2 running, D/U_a with one note; old leader holds both index locks and follower shared use. Move `/old` to `/new`: old follower refuses `root_changed`, old leader commits retirement with both rows failed/root_changed, closes/releases, while `/new` gets `I/H_new` at `G2` and the unchanged D/U_a. With no replacement `/old`, a later report shows both failed request IDs through 24 h; a non-report GC can retire still-pending rows under maintenance leadership if the old leader crashed, and a later post-quarantine GC deletes old derived cache. If `/old` is replaced by a different inode, open returns `root_retired` during quarantine; afterward verified exclusive use rebinds Q metadata, rebuilds at new generation and never executes old seq 1/2. A non-Git `/plain-old` moved to `/plain-new` leaves `D/path-H_old` disconnected/reportable; no new `D/path-H_new` until explicit save.

<a id="W04"></a>
### W04 — Use-lock inode race

Initially reader A holds shared `I.lock`, durable reader B holds shared `D.lock`, and DBs are open. GC/recreation and forget fail `busy` without deleting bytes. After readers close, an exclusive deleter verifies inode, removes recognized DB/sidecars, fsyncs parent, unlinks lock last; an opener previously waiting on the obsolete inode detects mismatch after flock, releases it, and retries against the new pathname (at most three identity-race retries, then `state_busy`). An unexpected symlink or member stops deletion with `unsafe_state`, retaining data; no traversal through it.

<a id="W05"></a>
### W05 — Leader crash and suspended takeover

Start `I/G1` reconciled to incarnation `U_old`; leader holds flock, follower holds shared use. Crash releases flock; with no current holder, evidence refuses `index_not_ready`. Successor wins and pauses immediately before its marker write: follower probes contention and can return old G1 snapshot if both checks fall in this window, with **no finite time bound** if successor is suspended. Once successor writes/fsyncs `U_new`, old marker snapshot refuses `index_not_ready`; successful full root-checked reconcile commits marker U_new and enables G1/new revision reads, while failed reconcile never enables them. A still-live but suspended leader retains flock indefinitely; no PID/timeout steals it.

<a id="W06"></a>
### W06 — Requests, crashes, and retirement ordering

Start active R, Q empty, leader at G1 with maintenance pending. Browser inserts seq 1/reconcile, CLI inserts seq 2/reconcile; both durable rows survive disconnect. Leader alternates pending maintenance and lowest-seq explicit work (startup reconcile first), claims with incarnation and at most three attempts. Crash before insert commit leaves no accepted row; after insert retains queued; after claim leaves running for successor; after index publish before done may rerun and advance internal revision twice, but no state regression. Same request_id and same operation/root returns existing row; different values refuse `request_conflict`. Third crashed claim reaches attempt limit and terminal `attempt_limit`; queued cancellation becomes cancelled; running cancellation before publish prevents commit, whereas after commit may still finish done. A requester with no leader self-elects and drains rows; waiting CLI can return queued/running after 30 s without cancellation. For retirement concurrency, insert transaction first means retirement includes it; retirement first fences insert as `root_retired`. On R move, old leader retires queued/running with root_changed before release, without scanning new occupant. Crash before retirement commit leaves original rows for recovery; crash after leaves terminal failures. With no replacement, later non-report GC under verified exclusive use takes maintenance-only leader lock, writes an old-root incarnation, retires rows without native scan, then releases. Busy, corrupt or failed retirement returns `request_retirement_pending`, leaves accepted rows and Q intact; report never pretends success.

<a id="W07"></a>
### W07 — Queue and retention bounds

Start Q active with 4096 nonterminals and no lock holder except short transactional appenders: a 4097th unique request waits/retries every 100 ms up to 5 s, then `queue_full` and **no row**; freeing one slot permits admission. With 4096 terminals, next terminal evicts oldest `(finished_ms,seq)` even inside 24 h; ordinary terminals older than 24 h prune first. An evicted request_id can be new work on resubmission, whereas retained ID deduplicates. Quarantined root_changed rows remain for at least 24 h despite ordinary pruning, within the cap because retirement first prunes older ordinary terminals. An incompatible/corrupt Q returns `requests_unavailable`, preserves bytes and accepted rows; never resets to an empty queue.

<a id="W08"></a>
### W08 — Watcher and zero-event input recapture

Begin with valid G1 files/tracked_inputs and leader watch. An event at 199 ms extends debounce, 200 ms quiet triggers a batch, and the first event's 2 s deadline caps endless extensions. 4096 distinct paths remain coalesced; path 4097 promotes full reconcile. Rename removes old path and adds new; ignore/config change, bulk, overflow, watch loss/limit and wake set full; a nonworking watcher uses poll-only 60 s reconciliation. Preserved mtime/same-size but changed ctime rehashes; a racy timestamp or backwards/unknown clock precision hashes conservatively; missing file deletes its row; three unstable read attempts refuse `unstable_input`. Events arriving before a long job's commit cause re-read/reassembly; after cutoff remain pending. With **zero watcher events** after G1, edit root `tsconfig.json` without changing its stat tuple, create previously absent `Cargo.lock`, remove `package.json`, and change nested `.ignore` to admit a source. The next 60 s full scan probes/hashes all four, recaptures directory/source inventory, and atomically publishes G1/new revision; failure at final recheck preserves G1/old rows and leaves reconciliation pending. Even ignored root config remains tracked; global/parent ignore rules are not read; a changed SourceSet descriptor requires reopen; changed pinned extractor executable refuses `toolchain_changed` until process restart. No exact 60 s completion promise follows from the timer.

<a id="W09"></a>
### W09 — Fact and capture limit boundaries

Initially two moved checkouts have different I/path keys and G1/G2 but identical `(language,extractorVersion,contextDigest,contentHash)`; the second reuses a path-neutral fact without old path or IDs. Changed context misses. Concurrent equal insert is idempotent; unequal payload same key emits `fact_conflict` and bypasses key. An exactly 8 MiB payload caches, 8 MiB+1 does not; eviction at 256 MiB or 100000 entries uses last_used_ms then PK byte order. Full/corrupt facts DB bypasses optional cache without changing publication. In an existing valid G1, accepted ceilings are 100000 admitted files, 2 MiB/source, 1 GiB source bytes, 1000000 combined rows, 512 MiB non-source payload, and 10 min/job; 100001 files, 2 MiB+1, or above any other cap refuses `scan_limit`/`job_timeout`, leaving G1 rows. Likewise accept 1024 SourceSets, 1 MiB total descriptors, 100000 visited directories (root included), 2 MiB each ignore/config/manifest input, 64 MiB combined such bytes, 256 MiB executable; 1025 SourceSets, descriptor total+1, 100001 visited, any non-source file+1, combined+1, or executable+1 aborts without publication. Binary `bun.lockb` is included and need not be UTF-8. Tracked rows and payload count toward shared row/non-source caps, not a hidden unlimited inventory; invalid/unreadable inputs fail rather than silently dropping.

<a id="W10"></a>
### W10 — Native reassembly is not semantic rebinding

Start G1 with native Call/dependency rows and a historical producer-captured unresolved CallBinding. Add matching Declaration; native dependency/surface diff reassembles affected Call/Declaration and dependent source sets in one transaction, producing G1/new revision syntax rows. The captured CallBinding remains unchanged in its historical artifact: no native resolved target, freshness promotion, or reassignment to a newly identified occurrence appears. Only a future producer refresh can supply semantic bindings; v1 requests admit no semantic import operation. Removing import/supertype/reexport invalidates corresponding native lookup dependencies; body-only edit reassembles its file without a surface-triggered workspace fanout. Exactly 256 changed files/4096 affected strings follow bounded dependency reassembly; 257/4097 or unknown scope forces whole workspace. Failure/pause before transaction commit leaves old Call, dependency and surface rows together. #22 alone decides retained artifact freshness and target checks.

<a id="W11"></a>
### W11 — Rebuild and exceptional recovery

Start I/G1 with valid Q accepted rows, D/U_a, facts and a WAL reader holding shared use. Schema/extractor mismatch blocks new reads, then leader atomically replaces index-owned tables within existing index.db, full-reconciles to G2/revision 1 and leaves Q/D/facts untouched; an already-open compatible WAL snapshot stays coherent subject to T04 checks. Failed in-place replacement rolls back G1 rows but cannot serve incompatible G1 schema. `SQLITE_CORRUPT`/`SQLITE_NOTADB` or unrecoverable format permits exclusive-use index.db/WAL/SHM recreation; SQLITE_BUSY/FULL, permission or I/O failure does **not**. Reader contention skips recovery, no killing; reader corruption closes connections/shared lock and may retry once after 100 ms. With exclusive use and leader lock verified, crash after unlink leaves missing index, next exclusive recovery finishes with new generation; creation/fsync failure yields `index_recovery_failed` without success marker. No old and new DB incarnation share a pathname while any old opener holds it.
